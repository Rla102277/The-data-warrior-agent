# The Battle Map

Maintain one short `BATTLE_MAP.md`, only for work that benefits from continuity. Record objective, terrain, dependencies, actions, risks, decisions linked to the Scroll, and proof. Also record current position, blockers, and the next action. Proof is a command, exit code, and artifact path — or an explicit statement that no proof exists yet. Distinguish verified, in progress, blocked, unknown and not started. At resumption, inspect actual code, Git and tests before trusting previous claims. Update at milestones, not after every trivial tool call. Never duplicate the Scroll or imply a checklist is proof. A failed or unrun test is not verified.

Follow project instructions and the installed THE_WAY.md. Use native host tools, respect permissions, and distinguish observed evidence from assumptions.
